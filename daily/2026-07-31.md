## 详细修复记录

### P0-1：解除 15s 硬超时
- **文件**：`system.ts`
- **改动**：两处 `setTimeout(15000)` → `PROXY_TIMEOUT_MS`（读环境变量，默认 300s）
- **影响**：视频生成长任务不再超时 504
- **验证**：>15s 请求不再出现 TIMEOUT 日志

### P0-2：SSE 流式转发（3 次迭代）
- **v1**：检测 Content-Type=text/event-stream → pipe 直传 + zlib 解压
- **v2（修复）**：`pip` → 保留 `data:` 前缀。前端用 `startsWith('data:')` 识别 SSE 行
  - **根因发现**：前端 `httpClient.js` 中：`if (!t.startsWith('data:')) continue`
  - 早期版本剥离了前缀导致前端全部跳过
- **v3（修复）**：非流式 chat 请求强制 `stream:false`
  - **根因发现**：网关 chat/completions 默认 `stream=true`，文本节点用 `await T.json()` 解析（不支持流）
  - 修复：检测无 `"stream"` 字段的 chat 请求 → 注入 `"stream":false`，让网关返回 JSON

### P0-3：协议翻译层（1 次修复）
- **改动**：两处非流式响应头 `content-length` 加入 skipHeaders
- **根因发现**：P0-3 剥信封后 body 变小（如 98→74 字节），Content-Length 仍为旧值，浏览器等缺失字节超时 → `failed to fetch`
- **修复**：`writeHead` 移到 P0-3 之后，Node 自动用 chunked 编码

### P0-4（新增）：异步生成转同步
- **文件**：`system.ts` → `handleAsyncPoll()`
- **根因发现**：前端图片节点用 `t.data[0].url` 同步取图片URL，但 flux.2-pro 是异步模型只返回 task_id
- **修复**：proxy 检测 images/videos 提交 → 自动轮询 `/v1/tasks/{id}` → 完成后返回 `{code:200, data: [{url:"...", status:"completed"}]}`
- **验证**：前端图片节点立即显示生成的图片

### L1：kv/delete

- **改动**：新增 `handleKvDelete` 函数 + 路由注册 `POST /api/kv/delete?key=`

## 调试中发现的隐藏问题

| 问题 | 影响 | 修复 |
|---|---|---|
| ESM `__dirname` 未定义 | 服务无法启动 | `fileURLToPath` |
| SSE `: heartbeat` 注释行 | 前端 JSON.parse 报错 | SSE 解析器过滤 |
| SSE `data:` 前缀缺失 | 前端 `startsWith('data:')` 跳过所有行 | 保留前缀 |
| 网关 chat 默认 `stream:true` | 文本节点 `T.json()` 失败 | 非流式强制 false |
| Content-Length 不匹配 | 浏览器等缺失字节 → failed to fetch | 移除 header 用 chunked |
| 异步生图 vs 同步解析 | 前端取不到 url → 显示"未生成" | proxy 内部轮询 |
