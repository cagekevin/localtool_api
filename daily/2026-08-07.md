## 四、画布右键导入·素材 tab 为空 —— 修复（方案 A：后端 save 统一 dataURL 落盘）

> 详见 `docs/34-画布右键导入-素材tab为空排查与素材系统梳理.md`（第 9 节）。核心：剪贴板粘贴只把 dataURL 塞进内存/SQLite、从不写真实文件 → 本地文件夹必空、刷新易丢。

### 根因确认（源码逐节点核对）

- 粘贴：`Vr.jsx:2050-2079` `readAsDataURL` → dataURL → `Ia(t,'image')`（`Vr.jsx:2085`）→ `url: e` 存 dataURL → `Ar()` 调 `POST /api/resources/save`。
- 后端 `handleResourcesSave`（`resources.ts`）此前只 `upsertResource`，**从不解码写盘** → 磁盘 `upload/migrated/` 永远空。
- 刷新后 `L` 靠 `xt()` 重建（`Vr.jsx:147`，有端口守卫），rescan 只扫磁盘、dataURL 记录无文件不接管 → 端口离线/清库时该素材永久丢失。

### 代码改动（仅后端 `localTool/src/routes/resources.ts`，约 +20 行）

1. import `writeUploadBuffer`（fileStore）
2. 新增 `decodeDataUrl`：解 dataURL base64 + MIME 推导扩展名
3. `handleResourcesSave` 开头：`url.startsWith('data:')` → `writeUploadBuffer(folder,'clip-<ts>.<ext>')` 落盘 → `body.url` 改写为 `http://127.0.0.1:18080/files/...` → 再 upsert。落盘失败不阻断。

### 现场验证（rescan / 数据核对）

- 服务 18080 在跑；`rescan` → `{scanned:303, added:0, skipped:303, orphanDeleted:0}`（磁盘文件全在库，库健康）。
- 库 311 条：`tasks:299`、`migrated:8`、`canvas:4`。
- 磁盘 `upload/`：`canvas:273`、`migrated:1`、`tasks:556`；`migrated/` 只有 1 个缩略图，无真实图。
- **直接证据**：库 `migrated` 中 1 条记录 url 是 `data:image/png;base64,...`，磁盘无对应文件 → 粘贴未落盘，正是空 tab 根因。

### 待办 / 边界

- 改后需**重启 localTool** 生效；改后**新粘贴**素材才落盘。
- 已存在的存量 dataURL 记录**不自动迁移**，如需恢复需一次性解码落盘（可选）。
- 远程 http(s) URL / AI 资产（`ci`/`hi`）不在本次范围（详见 docs 9.2）。
- 用户待测试：重启后重新粘贴图片 → 看 `upload/migrated/` 是否有文件 + 素材 tab 刷新不丢。
