## 〇、长期目标（总纲）

**一句话目标：把所有"本该直连官方 1mao（内置模型/权益/平台）"的请求，改道到 localTool 统一转发，由 localTool 决定实际转发给谁（官方 / Lovart / 其他 API / 本地兜底）。**

### 为什么
官方 1mao 闭源，账号/权益/会员判定 100% 在官方远程。当前前端这些请求**直连官方**（base 默认取官方候选地址，`docs/20` §7.1 实测），导致：
- 散乱裸连官方、来源判定混乱、无降级兜底；
- 本地自托管时仍依赖官方模型/权益（本地不可用）。

### 目标架构
```
前端【全部】请求
   │  改 src/bundle 后 base → 127.0.0.1:18080（npm run build 回灌 dist/）
   ▼
localTool（唯一出口网关，决定发给谁）
   ├─ 命中本地路由 ─┬─→ 本地处理（文件/任务/资源/KV）
   │                ├─→ Lovart / apimart-gateway
   │                ├─→ 其他 API / 网站（x-official-base / KV 覆盖）
   │                └─→ 本地静态清单兜底（内置模型，不依赖官方）
   └─ 未命中 ────────→ catch-all 兜底透传 → 官方 1mao（原样回传）
```

### 核心原则（2026-08-01 确立）
**不区分"该不该直连官方"—— 全部走 localTool。即使最终目的地仍是官方，也必须经 localTool 转发。**
localTool 从"白名单路由服务"升级为"唯一出口网关"，未接管的请求由 catch-all 透传，而非 404。
⇒ 由此派生一条**硬前置**：改 base 之前，必须先给 localTool 补 catch-all 兜底透传（详见 `docs/21` §六）。

### 落地方式：改 src/bundle，让前端 base 指向 18080
前端这些请求的 base 经 `g()`(u()||l()) 链默认取官方地址，且 `g()` 只读 sessionStorage、不读 KV——所以**必须改 `src/bundle/`**（把 base 指向 `http://127.0.0.1:18080` 后 `npm run build` 回灌 `dist/`）才能让请求走 localTool。这是方向一、五、六的**同一套 base 改造**。

### 各方向定位
| 方向 | 归属 | 一句话 | 状态(2026-08-02) |
|---|---|---|---|
| 一 官方权益转发层 | 改 src/bundle | 权益/会员请求走 localTool 转发官方（+缓存降级） | ✅ 已落地 |
| 二 特惠视频第三方 | 改 src/bundle | 注入式：第三方 API 视频模型并入特惠 `discountVideoModel` 清单（不改 url/key 通道） | ✅ 已落地（注入式最小集，见变更登记 #4） |

| 六 A1 画布助手 | 改 src/bundle | 助手 `/agent/*` 走 localTool/本地，不裸连官方 | 🟡 vip-check 已落地，chat 未本地化 |

## 二、特惠视频（discountVideo）支持第三方 API（✅ 已落地 2026-08-02 · 注入式最小集）

### 背景（现状）
特惠视频节点**只支持内置模型、不支持第三方 API**，原是**设计上的硬隔离**（非 Bug），根因是特惠节点整条链路与 `apiConfigs` 下拉**解耦**（详见 `docs/16`）：

| 维度 | 普通视频/图节点 | 特惠视频节点（discountVideo） |
|---|---|---|
| 模型下拉数据源 | `apiConfigs` 合并后的模型清单 | 硬编码字段 `discountVideoModel`（`\n` 拆分的纯文本） |
| API 地址 | 选中 apiConfig 的 `e3.apiUrl` | 固定字段 `discountVideoApiUrl`（闭包常量 `u2`） |
| 鉴权头 | 选中 apiConfig 的 `e3.apiKey` | 固定字段 `discountVideoApiKey`（闭包常量 `d2`） |
| 是否可切换 API 配置 | 是（内置+自建都出现，内置排前） | 否（面板无下拉入口） |

### ✅ 已落地（2026-08-02 · 注入式最小改动，非第 6 节重构方案）
**用户确认"能被识别为内置模型即可"**——即只要求特惠下拉里**能出现并选中**第三方视频模型，不要求切换 API 配置入口。据此采用最轻的"注入式"路径（详见 `docs/16` §9），**未采用** `docs/16` 第 6 节的"加 API 配置下拉 + 改 url/key 来源"重构方案：

- **做法**：在 `localTool/data/apiConfigs.baseline.json` 的 tehuishipin 条目下挂 video 模型（seedance-2.0-fast / seedance-2 / kling-v3-omni），前端运行时把这些 video 模型 id 经 `setDiscountVideoApiConfigModels` 注入全局，由 `Ki()` 合并进 `discountVideoModel` 列表回灌特惠面板。
- **关键修复**：首版 `Ki()` 在"云端 Ni 已加载"分支只返回 `isDiscountVideo` 模型，导致注入的第三方 video 模型被过滤→下拉为空；改为两个分支都追加、去重后解决（`docs/16` §9.2 改动 2）。
- **计费隔离零风险**：本方案**不改**特惠节点的 API 地址/鉴权来源（仍走 `discountVideoApiUrl`/`discountVideoApiKey` 锁死的特惠通道，经 localTool 网关），仅扩展可选模型清单，因此不引入 `docs/16` §6.4 担忧的"绕过特惠计费"风险。
- **生效要点**：重启 localTool 重新读 baseline + 刷新浏览器插件加载新打包产物（`npm run build` 回灌 dist）。首版仅重启 localTool 未刷新插件导致下拉仍空，已纠正。

### 前提与风险（完整重构方案才需关注，当前注入式不涉及）
> 以下为 `docs/16` 第 6 节"加 API 配置下拉 + 改 url/key 来源"重构路线才需评估的风险，**当前注入式最小集未触碰**，仅作未来若升级到"用户自选第三方 API 配置并切换通道"时参考：

- **计费/额度隔离（关键）**：若放开让用户切换第三方 API 配置，会**绕过特惠计费**，造成财务漏洞。建议白名单（`allowInDiscount` 标记）仅允许显式勾选的第三方进入特惠（`docs/16` §6.2 方案 A > 方案 B、§6.4）。
- **路径模板兼容**：普通节点拼 `/v1/gateway/task/...` 后缀。若第三方基址不同，需存完整基址或约定兼容网关地址（`docs/16` §6.7 注意）。
- **响应结构兼容**：第三方轮询状态码可能与特惠链路不一致，需做响应适配。

### ⚠️ 重要前提辨析（2026-08-01 补）：自研接管后「特惠」概念消解
「特惠视频」的本质**不是一种技术能力，而是官方的一套商业定价通道**——官方用锁死的 `discountVideoApiUrl` / `discountVideoApiKey` / `discountVideoModel` 把请求强制打到自己的特惠计费网关，从而给出低于常规的价格。

因此，一旦按〇总纲把模型改走**我们自己的 API**（localTool → apimart-gateway → Lovart / 第三方）：

- **计费主体变了**：账单由我们的上游供应商结算，官方特惠价不再适用；
- **「特惠 vs 普通」的区分失去意义**：两者都只是"选一个 apiConfig 发一个视频任务"，差别仅剩模型名与单价，不再有独立通道；
- **特惠节点本身沦为冗余**：它与普通视频节点的唯一差异（锁死的 url/key/模型）已被移除。

所以本方向存在两条互斥路线，需先做**业务决策**：

| 路线 | 做法 | 适用前提 |
|---|---|---|
| **A. 保留官方特惠** | 不动 `u2`/`d2`，特惠节点继续直连官方特惠通道；只放开"白名单第三方"作为补充 | 仍要吃官方特惠价，接受账号/权益依赖官方 |
| **B. 自研接管（推荐，与〇总纲一致）** | 特惠节点与普通视频节点**合并**，统一走 apiConfig 选择；不再保留"特惠"字样，或降级为一个普通的低价模型选项 | 已全面走自研链，不再依赖官方计费 |

> 结论：若走路线 B，则本方向的"让特惠支持第三方"实际等价于**删除特惠节点的特殊性**——不是加功能，而是**做减法**。下方"复用 apiConfig 机制"的改造方案，正是路线 B 的最小实现路径；路线 A 才需要额外做白名单与计费隔离。

### ✅ 业务决策结果（2026-08-02）
用户的实际诉求是"第三方视频模型能出现在特惠下拉并被选中即可"，**不要求切换 API 配置入口**。因此既不走 A 也不走 B 的完整重构，而是采用了**两者之外的"注入式最小集"**（见上方 ✅ 已落地）：仅把第三方 video 模型并入 `discountVideoModel` 清单，不动 url/key 通道、不动面板 UI。这是满足需求且零计费风险的最省方案。若后续确需"用户自选第三方 API 配置并切换通道"，再升级到路线 B 并补 §6.4 计费隔离。

### 落地入口（历史/重构路线参考）
改点在 `src/bundle/` 前端源码（对应 `App-BX6o9fW5.js` / `httpClient-BknZwXjG.js` 中的 `u2`/`d2`/`Ur`/`apiConfigs` 合并数组 `a3`），在 `src/bundle/` 实现后 `npm run build` 回灌 `dist/` 验证。**当前注入式已落地，详见变更登记 #4 与 `docs/16` §9。**
